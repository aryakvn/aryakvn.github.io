# Arya Kavian — Personality & Creative Direction

> **Purpose:** This document captures not only what Arya Kavian does professionally, but the personality, aesthetic, interests, and character that a personal website should communicate.
>
> **Audience:** Web designers, frontend developers, copywriters, and anyone responsible for shaping Arya's personal brand.
>
> **Important:** Some sections are based on publicly verifiable information, while others are informed interpretation. Interpretive observations should be treated as creative direction rather than biographical facts.

---

# 1. The Person Behind the Résumé

The biggest mistake the website could make is presenting Arya as simply:

> **"A developer who knows Vue, Django, Python, Docker, and AI."**

That description is technically useful but personally uninteresting.

The more interesting picture is someone who appears to be:

- technically curious
- independent-minded
- experimental
- interested in understanding systems beneath abstractions
- attracted to both old and new technology
- interested in AI without treating it as magic
- security-conscious
- aesthetically minded
- comfortable moving between engineering and creative interests
- someone who likes *how things work*, not merely *how to use them*

There is an important contrast in this personality:

> **Modern technology, old-school curiosity.**

Arya's interests span AI, LLMs, web development, cybersecurity, Linux, networking, and modern development tooling, while also extending into things such as old cars, photography, physical objects, card tricks, and vintage/classic aesthetics.

That contrast is potentially the strongest creative concept for the website.

---

# 2. Core Personality

## 2.1 Curious

Curiosity appears to be one of the strongest characteristics.

Arya doesn't seem satisfied with simply knowing that something works.

The recurring pattern is:

```text
What does this do?
        ↓
How does it work?
        ↓
What's underneath it?
        ↓
Can I build it myself?
        ↓
Can I change it?
        ↓
Can I make it better?
```

This is visible in the technical writing.

For example, an authentication article doesn't simply compare JWT and sessions. It explores HTTP, headers, cookies, session tokens, encrypted cookies, and the mechanics behind authentication.

Likewise, the Python/macOS article goes below the abstraction of "turn Python into an app" and explores application bundles, executables, virtual environments, loaders, and `Info.plist`.

### Website implication

The website should communicate:

> **"I like understanding things."**

rather than:

> **"I know many technologies."**

# 3. Builder Mentality

Arya appears to learn by building.

The public technical footprint spans:

- frontend development
- backend development
- deployment
- networking
- security
- AI
- robotics
- developer tooling
- automation
- operating systems
- infrastructure

The common thread isn't a particular framework.

It is:

> **Take an interesting problem and build something around it.**

This is why a portfolio based entirely around a chronological résumé would probably undersell him.

The website should feel more like a **collection of things built, investigated, and learned**.

# 4. Experimental Personality

There is a strong "let's see what happens" aspect to the technical interests.

Examples include:

- experimenting with LLMs
- local AI models
- computer vision
- robotics
- custom networking
- operating systems
- security tools
- custom software infrastructure
- unusual programming experiments

This suggests a personality closer to:

> **engineer + tinkerer**

than:

> **corporate software developer**

The website should therefore have some personality and experimentation in its interaction design.

Not excessive animation.

Not gimmicks.

Instead:

**small technical surprises.**

For example:

```text

arya
```

or an interactive terminal that reveals small pieces of information.

# 6. AI Personality

AI should be represented carefully.

Arya's AI work shouldn't be presented as:

> "AI enthusiast"

or:

> "Passionate about artificial intelligence."

Those phrases are generic.

The more interesting aspect is the intersection between:

**AI × Software Engineering × Security**

The LLMSecGuard research is particularly valuable here.

The project asks a very practical question:

> If AI generates software, how do we make sure that software is secure?

That is a much more distinctive position than simply saying:

> "I work with LLMs."

### Recommended positioning

> **Exploring what happens when AI becomes part of the software engineering process.**

or:

> **Building software around AI — and questioning the software AI produces.**

# 7. Security Personality

Security appears to be more than an isolated technical skill.

It connects naturally with the broader personality.

Authentication, networking, vulnerability detection, static analysis, honeypots, IDS concepts, and LLM-generated code security all fit the same general pattern:

> **Understand how systems fail.**

This creates an interesting engineering philosophy:

```text
Build it.
Understand it.
Break it.
Secure it.
```

This could actually become one of the site's recurring conceptual motifs.

# 9. Engineering + Craft

The interest in classic cars, photography, card tricks, and physical objects suggests appreciation for **craft**.

This is an important distinction.

A generic developer website communicates:

> Technology is a tool.

A more personal Arya website could communicate:

> **Technology is something you can understand, modify, and master.**

That philosophy applies equally well to:

- writing software
- tuning a car
- taking a photograph
- performing a card trick
- configuring a network
- experimenting with AI

There is a common attraction to **systems with hidden mechanisms**.

# 10. Aesthetic Personality

The visual identity should probably avoid the stereotypical "developer portfolio" look.

## Avoid

- excessive purple/blue gradients
- floating glassmorphism cards everywhere
- giant "Hello World"
- animated blobs
- excessive rounded corners
- dozens of technology logos
- generic stock photos of programmers
- "10x developer" language
- excessive cyberpunk aesthetics
- overused terminal animations
- AI-generated futuristic city backgrounds

These would make the site feel interchangeable.

---

# 11. Recommended Visual Direction

## Overall mood

**Dark · sophisticated · technical · personal · slightly nostalgic**

Potential visual vocabulary:

- charcoal
- black
- warm white
- muted green
- muted metallic tones
- subtle gray
- occasional amber/orange accent

Avoid making everything neon.

The site should feel more like:

> **a beautifully designed engineer's notebook**

than:

> **a gaming PC RGB dashboard**

- machinery
- architecture
- roads

- nighttime scenes

**technology → person → technology → person**

# 13. Typography

A combination of:

### Primary

A refined modern sans-serif.

### Secondary

A monospace font for:

- commands
- metadata
- dates
- technology names
- small labels
- technical details

Example:

```text
ARYA KAVIAN
SOFTWARE ENGINEER

LOCATION      IRAN
INTERESTS     AI / WEB / SECURITY
CURRENTLY     BUILDING THINGS
```

The monospace should be an accent, not the entire site's typography.

# 14. Website Tone of Voice

The writing should be:

- confident
- concise
- technically precise
- slightly understated
- curious
- occasionally playful
- never corporate

## Good

> I build software, break things occasionally, and try to understand why they broke.

## Good

> Mostly interested in software. Increasingly interested in what happens underneath it.

## Good

> I like building things that make me ask better questions.

## Avoid

> I am a highly motivated and passionate software engineer with a proven track record of...

That sounds like a résumé generator.

# 30. Motion

Animation should be:

**slow, deliberate, mechanical.**

Avoid:

**bouncy SaaS animations.**

Good:

- text appearing character-by-character in tiny areas
- mechanical transitions
- subtle image movement
- smooth scrolling
- understated hover effects
- terminal cursor blinking
- elements shifting like physical objects

Bad:

- particles everywhere
- constantly moving backgrounds
- excessive parallax
- spinning 3D objects
- flashy WebGL demos unrelated to content

# 38. Do / Don't

| DO | DON'T |
|---|---|
| Show curiosity | Say "passionate developer" |
| Show projects as stories | List technologies without context |
| Use subtle technical details | Turn the site into a terminal simulator |
| Include photography | Use generic developer stock photos |
| Show research prominently | Hide the paper in a résumé |
| Use restrained humor | Fill the site with memes |
| Use sophisticated dark visuals | Make everything neon |
| Show personality | Overshare personal information |
| Explain technical decisions | Brag about technologies |
| Use real photographs | Fill the site with AI-generated art |
| Make interactions meaningful | Animate everything |
| Let the site breathe | Put cards everywhere |

# 39. Final Creative Direction

The website should feel like you accidentally found the personal website of someone who:

**writes software during the day,**

**takes apart complicated things because they are interesting,**

**keeps a camera nearby,**

**has opinions about old machinery,**

**occasionally goes too deep into a technical rabbit hole,**

and **probably has three unrelated experiments running at the same time.**

It should be polished, but not sterile.

Technical, but not intimidating.

Personal, but not oversharing.

Minimal, but not empty.

Modern, but with some character.

The core feeling should be:

> ## **"There is a curious person behind this code."**

And the visual/technical metaphor tying the whole site together should be:

> ### **Everything has a mechanism. I'm interested in finding it.**
